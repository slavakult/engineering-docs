# История изменений

## Формат записей

При дальнейших обновлениях рекомендуется придерживаться следующего формата:

```markdown
## YYYY

### Месяц YYYY

#### Название изменения

- Что было добавлено.
- Что было изменено.
- Что было улучшено.

Подробнее: [название раздела](../path/to/documentation.md).
```

В Changelog следует включать значимые изменения, которые могут повлиять на работу пользователей или изменить поведение системы.

Не следует добавлять сюда:

· исправления опечаток;
· изменения форматирования документации;
· внутренние рефакторинги, незаметные пользователю;
· незначительные изменения интерфейса;
· промежуточные изменения, не попавшие в релиз.

Если изменение затрагивает API, дополнительно указываются изменённые методы или ссылки на соответствующий раздел API Reference.

Связь с документацией

При описании функционального изменения рекомендуется указывать ссылку на раздел документации, в котором подробно описана соответствующая возможность.

Например:

«Добавлена фильтрация задач по проекту и исполнителю.
Подробнее: Поиск и фильтрация задач.»

Это позволяет использовать Changelog не только как историю изменений, но и как точку входа к подробному описанию новой функциональности.
